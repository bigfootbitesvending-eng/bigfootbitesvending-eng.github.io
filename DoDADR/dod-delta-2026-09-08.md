# Definition of Done — proposed delta

**Date:** 2026-09-08
**Source:** HAHA Sales Ingestion / HAHA Sales Ingestion Orchestrator failure, 2026-09-08
**Destination:** Bigfoot Bites project instructions, DEFINITION OF DONE FOR CODE CHANGES
**Status:** Proposed. Route through the maintenance chat.

---

## Structural change: split the DoD into two phases

Every current DoD item is a pre-delivery check. Nothing in it survives the publish.

The 2026-08-29 merge fix in HAHA Sales Ingestion passed every existing DoD item and failed ten days later on the first execution that actually exercised it. The gap between published and proven had no owner.

Recommend adding a second phase header rather than appending to the existing list.

---

## Phase 1 — PRE-DELIVERY (existing list, plus the following)

### New: named references

**For every `$('Node Name')` reference, confirm the target executes on every path, not just before this node.** A node downstream of a loop, IF, Filter, or Switch is not guaranteed to execute. Where it is not guaranteed, guard the reference and supply an explicit zero-state object. The existing rule about guaranteed execution order covers ordering between parallel branches and does not cover a node that never runs at all.

### New: transplanted patterns

**When applying a pattern proven in another workflow, re-derive its preconditions at the destination and state them.** Renaming the nodes is not adaptation. List what the pattern assumes, then confirm each assumption holds here.

### New: zero-length output

**For every node emitting a variable-length array, state the intended zero-length behavior as skip, empty-render, or hard error.** All three exist in production today. The choice is recorded, not inferred. "It has never happened" is not a choice.

### New: cross-flow propagation

**When the change is a resilience or containment fix, check the sibling vendor flows and record the result.** Applies to error output wiring, continue-on-fail, loop isolation, retry, `alwaysOutputData`, timeout handling, and per-item error routing. A deliberate decision that a sibling does not need it closes the item. Silence does not.

### New: node names that assert guarantees

**Confirm any node whose name makes a behavioral claim actually behaves that way.** `Wait for All Sales Ingestion Branches` is a Merge in default append mode and does not wait. This generalizes the existing IF-gate naming convention from branch direction to any claim embedded in a name.

### Sharpening: verification claims

Replace the existing item "State what was verified, not just that verification happened" with:

**Every verification claim carries a citable artifact or is labeled not-checked.** Name the tool output that establishes it, not the conclusion drawn from it. "Confirmed the error handler is set" fails. "`settings.errorWorkflow` read from `get_workflow_details` on `Sn7IK9uJhiLAw4R6`" passes. Not-checked is a first-class and expected outcome. Inference presented inside a verified list is the specific failure this replaces.

---

## Phase 2 — VERIFICATION (post-publish)

**A change is done when an execution exercising the changed path has been inspected, not when it is published.**

Until then it remains an open item naming the specific execution that would close it. This applies to fixes that cannot be tested synthetically, which is most wiring and loop-behavior changes.

An item that stops appearing in a Flags block effectively stops existing. Published-but-unexecuted is an open state, not a completed one.

---

## Governance

Two rules to keep the list usable.

**Prefer sharpening an existing item over adding a new one.** Most findings are refinements of something already present.

**Retire items made structurally impossible.** A check that can no longer fail is scar tissue.

A candidate reaches the DoD only if it is verifiable before delivery (or, in Phase 2, verifiable against a named execution), binary, and cheap enough to run every time. Findings that fail that test are still valuable and route to an ADR or a backlog item instead.

## Not proposed for the DoD

Recorded here so the reasoning is not lost.

**Review isolated from authorship.** A fresh session, given only the delivered spec and a live MCP read and asked where live state diverges, does not share the flawed model that produced the error. This is the highest-leverage item discussed and it is not a checklist item, because the builder cannot self-administer it. It is a process change. Recommend scoping it to changes touching live production paths first, since a review that gets skipped is worth nothing.

**Write-path registry for ADR-governed columns.** The `transaction_time` ADR was accepted 2026-09-03 and enumerated three write paths. HAHA Sales Ingestion was updated 2026-09-07 as a fourth. Held pending a live query confirming what HAHA actually writes to that column, since the ADR may need revision rather than extension.
